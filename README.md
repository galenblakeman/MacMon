# MacMon

macOS resource monitor built with C# and Avalonia, using WinMon's portable MonCore library.

Choose **Compact view** or press **⌘⇧M** for a short live resource strip. **Full view** or **Escape** restores the dashboard and its selections. Compact mode and width restore on clean restart; full-window dimensions are kept separately. Settings and Always on top work in both views.

The full-width themed title bar keeps native Mac window controls, with **Info**, **Settings** and **Export** on the left and **Compact view** and **Always on top** on the right. Info groups supported hardware information into labeled sections with Refresh and Copy actions. Export opens a dialog for resource history, retained processes or session usage CSV, with all-retained/current-chart-range choices for history exports and a native file picker. Both full and compact views use the same dialogs. Buttons use WinMon’s vector icons, including its Export tray arrow, Always on Top windows, Capture frame/dot and More ellipsis. Auto, time chips and Individual/Grouped remain text-only.

The CPU, GPU, memory, disk and network readouts use WinMon’s 98-pixel layouts and seven gauge styles: **Bowl**, **Needle**, **Segmented arc**, **Left bar**, **Bottom bar**, **Segmented bar** and **None**. Choose a style under Settings → Appearance. The readout checkbox controls chart visibility. Hover or keyboard-focus a readout for a live tooltip with supported readings and measurement definitions; Escape dismisses it. Markers show live two-minute peaks. Disk gauges lead with estimated I/O activity (%) and show throughput below; network leads with download in bits/second and shows upload below. On supported Apple Silicon layouts, CPU speed shows a requested-state estimate from IOReport, explained in its tooltip; unsupported layouts show unavailable. Old Bar preferences migrate to Bottom Bar.

MacMon provides live system CPU usage, configurable resource history charts, estimated physical-memory usage, live memory pressure and available space on the data volume. The process list shows CPU averaged over five seconds, resident memory and thread counts. Switch between individual processes and executable groups, pin rows, filter to pins, and follow 30-second trends for the selected CPU/memory/thread/disk-I/O metric. Grouped memory shows a resident sum that can count shared pages more than once. Search by name or PID, sort by CPU/memory/threads/disk I/O/name/PID, and select a row to inspect its start time and executable path. Individual selection and pins follow a process lifetime, so a reused PID cannot inherit them. Group pins follow the exact executable path; pins and view preferences are saved on clean exit. Individual pins restore only within the same boot; group pins can follow later instances.

Network throughput follows the chosen interface (Automatic prefers an active Ethernet/Wi-Fi interface). Disk read/write rates follow the selected whole disk device, or aggregate all readable block-storage drivers. Under Settings → Monitoring, choose a primary disk and an optional second disk. Enabling the second disk adds its gauge, chart checkbox and Focus choice. Choices use GPT identities when available, with a boot-scoped identity for unidentified media; disconnected choices remain unavailable. Disk images can appear, while APFS volumes and partitions are excluded. Aggregate readings include any selected second disk. The data volume’s free space remains separate in Info. Arc gauges show each resource’s two-minute peak in the top-right corner, with a shorter percentage at narrow widths; network shows its rounded scale. Full and compact views use balanced tile insets. Gauge detail tooltips wrap to their popup width. The chart header combines Overlay, Small Multiples, Heatmap and per-resource Focus choices in one menu. Small Multiples and Heatmap stack vertically; Focus emphasizes one resource above the remaining lanes. Range chips sit on the right, Live/Capture in the center, and text-only Auto sits beside the chart selector, shows the capture count and opens capture settings and saved reports. Its tooltip reports whether automatic capture is enabled. Chart axis, time and resource labels use 12px text with a measured gutter wide enough for every tick. Inactive data tabs use theme-specific colors with readable contrast. Routine status text is kept out of the plot. Charts use WinMon’s translucent area fills (14% in focused/stacked views, 8% in overlay) and keep gaps between unavailable observations or changed sources. CPU/GPU/memory use 0–100%; network uses download bits/second and disk uses combined bytes/second. Disk gauges estimate I/O activity from accumulated read/write operation times divided by elapsed time, capped at 100%; operations and drivers can overlap, so this differs from Windows active time. Missing timing counters remain unavailable. Charts retain throughput units. Resource CSV columns `disk_active_percent` and `secondary_disk_active_percent` carry this Mac estimate. Layout, visible series and focus restore on restart. Process Disk I/O measures disk reads/writes only.

Hover the chart to preview readings without changing mode. Click the chart to open a captured-reading tooltip, or choose Capture to inspect retained process observations while recording and top readouts stay live. The X axis shows sample-clock times over the selected range. Focus the chart and use Left/Right to inspect samples, Home/End for visible boundaries, and Escape to return to Live. Choose 2, 10, 30 or 60 minutes to adjust the chart and retention limit; memory bounds can shorten retained history. Export resources or retained process samples as local CSV for all retained history or the selected chart range. Historical samples can omit idle processes; pressure/compressed details stay live. Enable **Keep history across restarts** under **Settings → Monitoring** to save bounded history on clean exit and reopen it in Capture mode; Usage totals begin fresh. Saved reports remain available across restarts.

Process and Usage column headers sort in either direction. Choose Top All/5/10/20/50/100; matching pinned process rows remain visible in addition to the unpinned limit. **App Only** filters executable paths inside `.app/Contents/MacOS`, including helpers and background apps; it does not mean apps with visible windows. Bundle icons come from macOS, with a generic fallback for inaccessible or missing bundles. The row’s pin button pins or unpins its exact process lifetime (or executable group). Selection action bars use WinMon’s heading, detail, right-aligned buttons and collapse control; buttons move below the heading at narrow widths. Process **More…** contains Pin and Reveal in Finder. Process columns show pin, process/PID, history, CPU, resident memory, disk I/O and threads. Histories share a scale across visible rows; rows have separators. Filters, limits and sort directions restore on clean exit; exports retain all applicable source data.

The tab order is **Processes**, **Jobs**, **Usage**, with counts/status aligned to the right of the tab row. Processes shows system process count and observed thread count. Pin actions appear at the left of process rows. All three tables align numeric headings with their values and keep a consistent scrollbar gutter. Usage totals observed CPU time and disk I/O by executable for this session, including exited apps. Its header offers Top, apps by, Search, App Only, Copy Usage and Reset. CPU time uses hours:minutes:seconds; process counts show seen (running). The selected-app bar offers properties, copy and Reveal in Finder. Export includes all session totals; Copy Usage includes displayed rows. Missing intervals are excluded.

Automatic captures can watch system CPU, estimated memory usage, network throughput or any process’s CPU. Configure thresholds, duration and cooldown with **Auto → Automatic capture settings…** or Settings → Automatic captures. A fired rule marks the peak on the chart and saves a local text report under `~/Library/Application Support/MacMon/Captures`; only the newest 200 MacMon-owned reports are kept. Choose a capture to inspect its retained peak or open its report after history expires. **Copy capture** copies the current resource summary and process rows with their averaging notes.

The **Jobs** tab monitors loaded launchd jobs in MacMon's current bootstrap context. Its header offers Top, jobs by, Search and status. Search label/PID/observed process, rank by label, reported state, PID, CPU, resident memory or disk I/O, refresh, and inspect/copy read-only properties. Verified direct-process readings and 30-second histories are shown separately from the reported job state; missing, stale or changed lifetimes remain unavailable. Child workers are excluded. It refreshes every five seconds while visible and preserves selection. Scope and observation time are explicit; failures retain stale rows with a warning. “Not running” does not mean disabled, and last exit status does not describe current health. Process details require a fresh matching lifetime. Other domains, disabled-job configuration and child-worker attribution are outside this inventory; there are no job-control actions. Jobs remain live when the resource chart is in Capture mode. The selected tab and Jobs sort/filter restore on clean restart.

Open **Settings…** or press **⌘,** for General, Appearance, Monitoring and Automatic captures. One Save applies all sections immediately and writes preferences; Cancel discards edits. Settings reopens to the last section used during the app session. The **Auto** menu’s settings shortcut opens that section directly.

General offers **English**, **Español**, or the system language, macOS **Open at login**, a last/full/compact startup view, and an optional global shortcut. The recommended shortcut is **⌃⌥M**; shortcuts are off by default and work while MacMon is running. Login-item registration and notification permission change only when you enable them and save in the packaged app.

Appearance offers System/Light/Dark plus 12 WinMon finishes and 19 palettes with color swatches. Display names match WinMon, including Midnight, Evergreen, Frost, Sapphire, High-Contrast, Sophisticated, Vibrant and Earth Tones; saved identifiers remain compatible. Every theme change selects its paired palette; you can then choose a custom palette. Settings pairs field labels and inputs on the same row. A local preview keeps draft appearance changes separate from the running app. Monitoring groups history retention, whole-disk selection and network selection. Automatic Capture has CPU, GPU, memory, network and process rules, a configurable report folder and optional notifications. Each folder keeps its newest 200 MacMon reports; changing folders leaves existing reports in place.

Sampling, ranking, selection and bounded history run through MonCore. Baselines, failed readings and wake gaps appear as unavailable CPU readings instead of zero. macOS may deny access to some processes; the list reports unavailable readings and retries without requesting elevated privileges.

Requires macOS, Python 3 for local-package normalization, and the .NET 10 SDK (validated with 10.0.401).

```sh
bash tools/bootstrap-moncore.sh
bash tools/verify.sh --smoke
dotnet run --project src/MacMon -c Release --no-build
```

The bootstrap script uses a sibling `../WinMon` checkout by default, or accepts its path as the first argument. It builds **MonCore 3.4.1-macos.1** from a pinned upstream commit plus the [portable identity handoff patch](dependencies/moncore/README.md), runs the portable tests and writes the package to the ignored local feed. An existing checkout's branch and working files remain intact. MacMon references that exact package; shared source stays in WinMon. No external NuGet publication is needed.

To create a self-contained local application:

```sh
bash tools/package-app.sh
open artifacts/osx-arm64/MacMon.app
```

The bundle and versioned ZIP/checksum are ad-hoc signed for development. Close the running packaged app before rebuilding its bundle. Intel packaging accepts `osx-x64`; execution still requires validation on Intel hardware.

For distribution, `bash tools/package-release.sh RUNTIME 'Developer ID Application: …' KEYCHAIN_PROFILE` verifies a clean committed checkout, signs with hardened runtime, submits for notarization, staples and assesses the app, then creates a ZIP/checksum and release manifest. This command uploads the app to Apple. A Developer ID Application certificate/private key and a configured `notarytool` keychain profile are required. Actual Developer ID notarization remains unverified on this machine; see the development notes.

Select a process for Properties, Copy details, Reveal in Finder and a confirmed termination request. Termination uses a captured process generation, protects system/other-user/MacMon targets, and excludes processes started after confirmation opens. Historical views disable termination. Always on top, ranking/grouping, pins, history range, network selection, capture rules, pane ratio and window size restore on restart. Preferences live at `~/Library/Application Support/MacMon/settings.json`; invalid files are preserved and defaults are used.

GPU reports device-wide IOAccelerator utilization for one stable adapter where the driver exposes it. Shared memory is labeled separately; per-process GPU and dedicated VRAM capacity are unavailable. IOReport frequency and IOAccelerator statistics are optional, undocumented interfaces; native validation currently covers the M2 Pro. Unsupported hardware and missing readings remain unavailable. See [development notes](docs/DEVELOPMENT.md) for contracts, verification and remaining work.

Table searches include clear buttons. Right-click rows for their actions; Jobs stays read-only. Usage’s **Show processes** returns to Live and filters by the exact executable path (`path:…`). Click Jobs column headings to sort or reverse direction.

Memory uses adaptive binary units (KiB/MiB/GiB); I/O rates and totals use decimal units (KB/MB/GB), with one decimal throughout. I/O columns describe disk reads and writes, excluding network traffic.

Collapsing or expanding an action bar applies across Processes, Jobs and Usage and is remembered on restart.
